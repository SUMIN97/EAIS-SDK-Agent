# eais debug — User Guide

`eais debug` is a command that analyzes conversion output.
With the `--mode` option, you can run **accuracy validation (accuracy)**, **browser visualization (visualize)**, or **both (all)**.

## Command

```bash
eais debug --w <workspace_path> [--mode accuracy|visualize|all] [options...]
```

## Options and Parameters

CLI options (`--<key>`) and `Config/debug.yaml` parameters share the same key names, and values passed via CLI take precedence over yaml values.

| Key | Default | Applicable Modes | Description |
|---|---|---|---|
| `--w` | current working directory | all | Workspace path. CLI-only. |
| `mode` | `accuracy` | all | Execution mode. `accuracy` / `visualize` / `all`. |
| `host` | `None` | `visualize`, `all` | IP address or hostname to use in the browser URL. Typically `127.0.0.1`. Required. |
| `port` | `None` | `visualize`, `all` | Port to use in the browser URL. Typically `40090`. Required. |
| `base_model_path` | `None` | `visualize`, `all` | Path to the base model file to open in the browser (`.snc` / `.onnx`). Required if `accuracy_result_path` is not specified. |
| `base_encodings_path` | `None` | `visualize`, `all` | Path to the base model's quantization encodings file (`.encodings`). Optional. |
| `base_external_data_path` | `None` | `visualize`, `all` | Path to the base model's ONNX external data file (for models exceeding 2 GB). Optional. |
| `base_activation_path` | `None` | `visualize`, `all` | Path to the base model's testvector `tvs` folder generated by `accuracy` mode. Optional. |
| `compare_model_path` | `None` | `visualize`, `all` | Path to the model file to diff-compare against `base_model_path`. Optional. |
| `compare_encodings_path` | `None` | `visualize`, `all` | Path to the compare model's quantization encodings file. Optional. |
| `compare_external_data_path` | `None` | `visualize`, `all` | Path to the compare model's ONNX external data file. Optional. |
| `compare_activation_path` | `None` | `visualize`, `all` | Path to the compare model's testvector `tvs` folder generated by `accuracy` mode. Optional. |
| `accuracy_result_path` | `None` | `visualize`, `all` | Path to the accuracy result file (`.xlsx` / `.csv`) to load together in the browser. Optional. |
| `pipeline_artifacts` | `Debug_result/pipeline_artifacts.json` | `accuracy`, `all` | Path to `pipeline_artifacts.json` generated after running `eais conversion`. Required. |
| `depth` | `full` | `accuracy`, `all` | Validation scope. `endpoints`: validates only the final output. `full`: validates outputs of all recorded conversion stages. |
| `metrics` | `[SNR, PSNR, COSSIM]` | `accuracy`, `all` | List of accuracy metrics to use. Defaults to the three metrics `SNR`, `PSNR`, and `COSSIM`. See [Metrics](#metrics) for available metrics. |
| `thresholds` | `[10.0, 10.0, 0.5]` | `accuracy`, `all` | PASS/FAIL thresholds mapped 1:1 with `metrics`. For SNR, PSNR, COSSIM, PASS if value ≥ threshold; for MAX_ABS_DIFF, MSE, PASS if value ≤ threshold. |
| `snc_input_name_mapping` | `exactly` | `accuracy`, `all` | Method for mapping input data folder names to SNC model input names. `exactly`: matches only when names are completely identical. `postfix`: first matches identical names, then among remaining pairs where one name is a prefix of the other (`b.startswith(a)` or `a.startswith(b)`), selects candidates with the smallest length difference. |
| `testvector_name_mapping` | `exactly` | `accuracy`, `all` | Method for mapping testvector names between models. `exactly`: matches only when names are completely identical. `postfix`: first matches identical names, then among remaining pairs where one name is a prefix of the other (`b.startswith(a)` or `a.startswith(b)`), selects candidates with the smallest length difference. |
| `save_layerwise_output` | `true` | `accuracy`, `all` | When set to `true`, saves per-layer output values as `.npy` files under `Debug_result/accuracy_validation_results/<stage>/tvs/`. |

### `mode` Values

| Value | Description |
|---|---|
| `accuracy` | Compares outputs of each `conversion` stage against the original model (`0_INPUT`) and measures accuracy metrics (SNR, PSNR, COSSIM, etc.). Uses the npy files in `Config/DATA/input_data/` generated by `eais generation` as inference input data. |
| `visualize` | Visualizes model graph/layer structure or accuracy results in the browser. |
| `all` | Runs `accuracy` followed by `visualize` in sequence. |

## Prerequisites

> [!WARNING]
> When using `--mode accuracy` / `--mode all`: `eais conversion` must be completed and `<workspace>/Debug_result/pipeline_artifacts.json` must exist.

> [!NOTE]
> When using `--mode visualize` / `--mode all`: please set `--host` and `--port` to `127.0.0.1` and `40090` respectively. The debug backend runs on port `40090` by default. If that port is occupied by another process (Jupyter, etc.), the error `[ERROR] backend did not become ready in time` may occur.

## `--mode` Summary

| `--mode` | Description | Required Options |
|---|---|---|
| `accuracy` (default) | Computes accuracy metrics (SNR, PSNR, COSSIM, etc.) between outputs of each conversion module. Results are saved to `accuracy_comparison.xlsx` and `accuracy_comparison_csv/` | (none) |
| `visualize` | Browser-based visualization. Three features can be used individually or in combination:<br>(1) **Single-model visualization** — `--base_model_path` (`.snc` / `.onnx`), optionally with `--base_encodings_path` and `--base_external_data_path`<br>(2) **Two-model diff comparison** — Adding `--compare_model_path` shows node-level diff between base/compare models. Optionally with `--compare_encodings_path`, `--compare_external_data_path`<br>(3) **Accuracy result visualization** — Preload `.xlsx` / `.csv` results in the browser via `--accuracy_result_path`. Can also be used standalone without a model | At least one of `--base_model_path` or `--accuracy_result_path` is required |
| `all` | Runs `--mode accuracy` followed by `--mode visualize` in sequence | At least one of `--base_model_path` or `--accuracy_result_path` is required |

## Description by `--mode`

### `--mode accuracy` (default)

#### Features

Based on the `pipeline_artifacts.json` left by `eais conversion`, this compares the output of each conversion stage in pairs and **computes accuracy metrics (SNR, PSNR, COSSIM, etc.)**.
When `depth=full` (default), all combinations of the 5 stages below are compared.

```
0_INPUT → 1_converter → 2_optimizer → 3_quantizer → 4_specifier
(original) (CNNX conv.)  (optimize)    (quantize)    (HW optimize)
```

Layers that do not meet the threshold for each metric are marked as **FAIL**. For metric/threshold details, see [Accuracy Validation Result Interpretation](#accuracy-validation-result-interpretation).

#### CLI Examples

**Default execution — the parameters from `Config/debug.yaml` are used as is.**
```bash
eais debug --w ./hrnet_pose
```

**Explicitly specifying `--mode` (same as default).**
```bash
eais debug --w ./hrnet_pose --mode accuracy
```

**Validate only the final stage (`0_INPUT VS 4_specifier`) — only 1 CSV is generated.**
```bash
eais debug --w ./hrnet_pose --depth endpoints
```

**Customize metrics and thresholds (metrics and thresholds map 1:1 in order).**
```bash
eais debug --w ./hrnet_pose \
  --metrics '["SNR","PSNR","COSSIM","MAX_ABS_DIFF"]' \
  --thresholds '[20.0, 30.0, 0.9, 0.01]'
```

**Disable per-stage `.npy` feature map saving (save disk space).**
```bash
eais debug --w ./hrnet_pose --save_layerwise_output false
```

> [!WARNING]
> Running `--mode accuracy` requires `<workspace>/Debug_result/pipeline_artifacts.json`. If missing, first complete `eais conversion`.

#### Output

| File | Content |
|---|---|
| `Debug_result/debug_report.json` | Overall validation success indicator (`"valid": true/false`) — the simplest PASS/FAIL check |
| `Debug_result/accuracy_validation_results/validation_report.json` | Per-layer detailed PASS/FAIL, metric values, list of FAIL causes (`fail_list`) |
| `Debug_result/accuracy_validation_results/accuracy_comparison.xlsx` | All comparison pair metrics consolidated into a single Excel file (separated by sheet per pair) |
| `Debug_result/accuracy_validation_results/accuracy_comparison_csv/` | Same content split into per-pair CSVs (`0_INPUT VS 4_specifier.csv`, etc.) |
| `Debug_result/accuracy_validation_results/<step>/tvs/*.npy` | Per-stage feature maps saved when `save_layerwise_output: true` |

For the full file tree, see [Output File Structure](#output-file-structure).

#### Result Interpretation

| What to Check | Where to Look |
|---|---|
| Overall PASS/FAIL | The `"valid"` field in `debug_report.json` (true = all layers passed) |
| List of FAILed layers | `results.AccuracyValidator.fail_list` in `validation_report.json` — SNR/PSNR/COSSIM values per layer and which metrics FAILed |
| Detailed metric value comparison | `accuracy_comparison.xlsx` (all) or `accuracy_comparison_csv/<pair>.csv` (per pair) |
| Actual tensor data for a specific stage | `accuracy_validation_results/<step>/tvs/*.npy` (`save_layerwise_output: true`) |

- For details on metrics, thresholds, and recommended SNR criteria, see [Accuracy Validation Result Interpretation](#accuracy-validation-result-interpretation).
- For CSV column meanings and `shape` vs `reshape` rules, see [accuracy_comparison_csv Interpretation Guide](#accuracy_comparison_csv-interpretation-guide).
- To view metrics as graphs in the browser, see [Standalone Accuracy Result Visualization](#standalone-accuracy-result-visualization-without-model) below.

### `--mode visualize`

#### Features

Launches the debug backend and renders the specified resources as browser graphs.
The 6 use cases below can be combined, and **at least one** of `--base_model_path` or `--accuracy_result_path` must be specified.

| Case | Key | Result URL |
|---|---|---|
| Single-model visualization | `--base_model_path` (+ `--base_encodings_path` if needed) | `?model=<uuid>` |
| Standalone accuracy result visualization (no model) | `--accuracy_result_path` | `?validator=<uuid>` |
| Model + accuracy result visualization | `--base_model_path` + `--accuracy_result_path` | `?model=<uuid>&validator=<uuid>` |
| Two-model comparison (compare diff) | `--base_model_path` + `--compare_model_path` | `?model=<uuid>&compare=<uuid>` |
| Single-model + activation tensor visualization | `--base_model_path` + `--base_activation_path` | `?model=<uuid>` |
| Two-model comparison + activation tensor visualization | `--base_model_path` + `--compare_model_path` + `--base_activation_path` + `--compare_activation_path` | `?model=<uuid>&compare=<uuid>` |

#### Single-model Visualization

**SNC model visualization — the most basic way to check the final conversion result.**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result/HW_output_new_snc_9.6.26.30.snc \
  --host 127.0.0.1 \
  --port 40090
```

**ONNX + encodings model visualization — load quantization encodings together to check each node's scale/offset info on the graph.**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result/2_mixed_precision_quantization/output.onnx \
  --base_encodings_path ./Converter_result/2_mixed_precision_quantization/output.encodings \
  --host 127.0.0.1 \
  --port 40090
```

**ONNX model over 2GB visualization — specify external data file together (for large models such as LLM).**
```bash
eais debug --w ./llama_workspace \
  --mode visualize \
  --base_model_path ./Converter_result/llama.onnx \
  --base_external_data_path ./Converter_result/llama.onnx.data \
  --host 127.0.0.1 \
  --port 40090
```

- Opens the base model directly in the browser without accuracy validation.
- When loading an ONNX model, specifying the `.encodings` file with `--base_encodings_path` shows a graph reflecting quantization information.

#### Two-model Comparison (Compare Diff)

**ONNX after quantization (base) vs final SNC (compare) — check how nodes are inserted/transformed in the quantization/compilation pipeline (the most commonly used combination).**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result/2_mixed_precision_quantization/output.onnx \
  --base_encodings_path ./Converter_result/2_mixed_precision_quantization/output.encodings \
  --compare_model_path ./Converter_result/HW_output_new_snc_9.7.3.30.snc
```

**SNC (base) vs SNC (compare) — compare final SNCs before/after SDK version upgrades or option changes side by side.**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result_v9.7.3/HW_output_new_snc_9.7.3.30.snc \
  --compare_model_path ./Converter_result/HW_output_new_snc_9.7.9.30.snc
```

**Both base and compare encodings specified — compare two ONNX models together with quantization info.**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./old/output.onnx \
  --base_encodings_path ./old/output.encodings \
  --compare_model_path ./new/output.onnx \
  --compare_encodings_path ./new/output.encodings
```

- Load the base and compare models together in the browser to view diffs at the graph/node level.
- Commonly used combination: **ONNX after quantization (+encodings)** vs **final SNC** → check how nodes have changed through the quantization/compilation process.
- Example output:
  ```
  [INFO] Uploading base: output.onnx, output.encodings ...
  [INFO] base model UUID: bd44b8f6-a6d2-434c-ac0e-70070bcc3966
  [INFO] Uploading compare: HW_output_new_snc_9.7.9.30.snc ...
  [INFO] compare model UUID: 691c1ae1-05c0-4e15-8d2d-d8847260b59c
  [URL] http://127.0.0.1:40090/?model=bd44b8f6-...&compare=691c1ae1-...
  ```

> [!NOTE]
> To specify `--compare_model_path`, you must also specify `--base_model_path`. If the compare model has encodings/external data, specify them via `--compare_encodings_path` and `--compare_external_data_path` respectively.

| Green border | Right (compare) | Layer that does not exist in the left model — layer added in compare |
| Yellow border | Both sides | Layer with the same name but with changed attribute values, etc. |

#### Activation Tensor Visualization (`--base_activation_path` / `--compare_activation_path`)

Running `--mode accuracy` (or `--mode all`) with `save_layerwise_output: true` saves per-layer output values for each conversion stage as `.npy` files. Specifying that directory with `--base_activation_path`/`--compare_activation_path` allows you to **check activation tensor distribution (histogram) when clicking nodes** directly in the browser UI.

> [!NOTE]
> The directory specified by `--base_activation_path` must be pre-generated by running `eais debug --mode accuracy` with `save_layerwise_output: true` (default). The location is `Debug_result/accuracy_validation_results/<stage>/tvs/`.

**Single model + base activation visualization — check per-layer activation distribution while viewing the SNC graph.**
```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result/HW_output_new_snc_9.7.9.30.snc \
  --base_activation_path ./Debug_result/accuracy_validation_results/0_INPUT/tvs
```

Clicking an edge displays a histogram in the **ACTIVATION DISTRIBUTION** section of the right inspector, and clicking opens an enlarged activation distribution window.

## Accuracy Validation Result Interpretation

### What is a testvector?

A **testvector** is output tensor data (`.npy` file) saved at each conversion stage of `eais conversion`.
After conversion completes, outputs of each stage — `0_INPUT` (original model output), `1_converter`, `2_optimizer`, `3_quantizer`, `4_specifier` — are saved as testvectors, and `eais debug` loads them to compute accuracy metrics between stages.

---

### Validation Method

Compares the output of each stage in the conversion pipeline in pairs against the original model (`0_INPUT`) and adjacent stages.
When `depth=full` (default), all combinations between stages are compared.

| Pair Example | Meaning |
|---|---|
| `0_INPUT VS 1_converter` | Original ONNX vs after CNNX conversion |
| `0_INPUT VS 4_specifier` | Original ONNX vs final SNC |
| `3_quantizer VS 4_specifier` | After quantization vs after SNC conversion |

---

### Metrics

| Metric | Meaning | PASS Condition |
|---|---|---|
| **SNR** | Signal-to-noise ratio (dB). Higher is closer to original | value ≥ threshold |
| **PSNR** | Error ratio based on maximum signal value (dB). Higher is more precise | value ≥ threshold |
| **COSSIM** | Cosine similarity between two vectors. Closer to 1 means same direction | value ≥ threshold |
| **MAX_ABS_DIFF** | Maximum absolute error between two tensors. Smaller means less numerical error | value ≤ threshold |
| **MSE** | Mean squared error between two tensors. Smaller means less overall error | value ≤ threshold |

> [!NOTE]
> Per-metric thresholds are set 1:1 with `metrics` in `thresholds` of `Config/debug.yaml`.
> **PASS** if all metrics meet thresholds; **FAIL** if any is below.

---

### PASS/FAIL Determination

The overall result can be checked in the `status` field of `validation_report.json`.

```json
{
  "results": {
    "AccuracyValidator": {
      "status": "FAILED",
      "fail_list": [
        {
          "name": "(base_edge_name: /layer1/0/conv3/Conv_output_0, ...)",
          "code": "UnderMetricThreshold",
          "info": {
            "SNR": [26.29, "MetricStatus.FAIL"],
            "PSNR": [59.38, "MetricStatus.PASS"]
          }
        }
      ]
    }
  }
}
```

- `status: PASSED` — all layers passed the threshold
- `status: FAILED` — one or more layers failed to meet the threshold
- `fail_list` — list of FAILed layers and their metric values

---

### SNR Result Interpretation Criteria

Pass criteria per precision are relative, and the following are recommended criteria. The default thresholds in `debug.yaml` are **10dB** for both SNR/PSNR and **0.5** for COSSIM.

| `precision` | Recommended Pass Criterion (SNR) |
|---|---|
| `FP16` | 35 dB or higher |
| `A16W8` | 30 dB or higher |
| `A8W8` | 20 dB or higher |

**Actions to try when SNR is low:**

1. Change `calibration_method` in the order `minmax` → `percentile` → `histogram_enhanced`
2. Upgrade `precision` in the order `A8W8` → `A16W8` → `FP16`
3. Rewrite `dbgen_spec.yaml` with a real representative dataset, then rerun `generation` → `conversion`
4. Consider applying `advanced_quantization_algorithm: smoothquant`

---

### Warning Message Interpretation

| Warning | Meaning | PASS/FAIL Impact |
|---|---|---|
| `Unmatched tensors` | Layers excluded from comparison because tensor names did not match between two stages (occurs when the optimizer changes layer structure) | None |
| `Shape mismatch ... ReshapeRule` | Output shapes differ, so permutations are automatically searched to attempt matching (e.g., removing SNC's batch dimension) | None (if matching succeeds) |

## accuracy_comparison_csv Interpretation Guide

Inside the `accuracy_comparison_csv/` directory, CSV files are generated per comparison pair.
Example: `0_INPUT VS 4_specifier.csv` — per-layer accuracy comparison result between the original model (base) and the final SNC (target).

---

### How to Read Filenames: base VS target

```
0_INPUT VS 4_specifier.csv
  └── base ──┘  └── target ──┘
```

- **Left of VS** = **base** (reference stage, comparison reference value)
- **Right of VS** = **target** (stage to compare)
- `0_INPUT VS 4_specifier` means "comparing the final SNC result against the original ONNX as reference."

---

### Row Order

Rows in the CSV are sorted in the following order:

1. **output** — the model's final output tensors
2. **input** — the model's input tensors
3. **intermediate layers** — listed in graph node order (topological order)

That is, they appear in the order output → input → graph.

---

### Column Descriptions

| Column | Description |
|---|---|
| `match_status` | Tensor matching result between two stages. `matched`: a corresponding tensor exists in both stages. `unmatched_base`: exists only in the base stage (no target). `unmatched_target`: exists only in the target stage (no base) |
| `base_name` | Base stage tensor name (key used for matching) |
| `target_name` | Target stage tensor name (empty if `unmatched_base`) |
| `SNR` | Signal-to-noise ratio (dB). Higher is closer to original. Stored as `(value, 'PASS'/'FAIL')` |
| `PSNR` | Error ratio based on maximum signal value (dB). Higher is more precise. Stored as `(value, 'PASS'/'FAIL')` |
| `COSSIM` | Cosine similarity. Closer to 1 means same direction. Stored as `(value, 'PASS'/'FAIL')` |
| `base_shape` | **Original shape** of base tensor (shape as saved in the `.npy` file) |
| `target_shape` | **Original shape** of target tensor |
| `base_reshape` | Base tensor shape **actually used** for accuracy comparison (after applying reshape rule) |
| `target_reshape` | Target tensor shape **actually used** for accuracy comparison (after applying reshape rule) |
| `best_perm` | The **axis permutation** applied by the reshape rule to the target tensor. `(0, 1, 2)` means used as is without permutation |
| `base_min` / `base_max` | Min/max value of base tensor |
| `target_min` / `target_max` | Min/max value of target tensor |
| `base_path` | Path to the base tensor's `.npy` file |
| `target_path` | Path to the target tensor's `.npy` file |
| `base_layer_name` | Name of the layer producing this tensor in the base stage |
| `target_layer_name` | Name of the layer producing this tensor in the target stage |
| `base_layer_optype` | Operation type of the base layer (e.g., `Conv`, `Relu`, `Input`, `Output`) |
| `target_layer_optype` | Operation type of the target layer |

---

### `shape` vs `reshape` Difference

| Column | Meaning |
|---|---|
| `base_shape` / `target_shape` | **Original shape** as saved in the `.npy` file |
| `base_reshape` / `target_reshape` | **Shape actually used for comparison** after applying the reshape rule |

Before comparing two tensors, the **reshape rule** performs the following processing:

1. **Remove size-1 dimensions (squeeze)**: removes unnecessary batch dimensions from both tensors.
   Example: `base_shape=(1, 17, 64, 48)` → `base_reshape=(17, 64, 48)`
2. **Axis permutation search**: tries all axis combinations of the target tensor and selects the arrangement that maximizes SNR against base. This result is recorded in `best_perm`.
3. **Shape matching**: rearranges target to match base's shape with the selected permutation.

As a result, when `shape != reshape`, the batch dimension (`1`) has been removed;
when `best_perm` is not `(0, 1, 2)`, an additional axis permutation has been applied.

## Troubleshooting

### 1. `FileNotFoundError: pipeline_artifacts.json not found`

Occurs when `Debug_result/pipeline_artifacts.json` is missing while running `--mode accuracy` / `--mode all`.

```
FileNotFoundError: pipeline_artifacts.json not found:
  /home/user/eais-projects/01-5_model/Debug_result/pipeline_artifacts.json.
To generate it, run 'eais conversion' again in the workspace directory.
  e.g.) eais conversion --w <workspace_path>
```

**Cause:** Not generated if `eais conversion` was not run or failed midway.

**Resolution:** Complete `eais conversion` normally, then rerun `eais debug`.
```bash
eais conversion --w <workspace_path>
eais debug --w <workspace_path>
```

---

### 2. `[ERROR] base model file not found: <path>`

Occurs when the file specified by `--base_model_path` in `--mode visualize` does not exist.

**Resolution:** Specify an actual existing model file path.
```bash
ls Converter_result/HW_*.snc      # check the actual filename
eais debug --w <workspace> --mode visualize \
  --base_model_path ./Converter_result/HW_<model>_<version>.snc \
  --host 127.0.0.1 --port 40090
```

---

### 3. `Error: Invalid value for '--mode'`

Occurs when an unsupported value is passed to `--mode`.

**Resolution:** Use one of `accuracy`, `visualize`, `all`.

---

### 4. Missing Required Options for `--mode visualize` / `--mode all`

Occurs when neither `--base_model_path` nor `--accuracy_result_path` is specified when running `--mode visualize` or `--mode all`.

```bash
eais debug --w ./hrnet_pose \
  --mode visualize
# Error: --mode visualize requires at least one of: --base_model_path, --accuracy_result_path
```

**Resolution:** At least one of `--base_model_path` or `--accuracy_result_path` must be specified. If using `--compare_model_path`, `--base_model_path` must also be specified.

```bash
eais debug --w ./hrnet_pose \
  --mode visualize \
  --base_model_path ./Converter_result/HW_output_new_snc_9.6.26.30.snc
```
