2왜 만들었나

출발점은 "지금은 SDK 를 직접 사용할 수 없다"는 상황이었습니다. 모델을 NPU 용으로 변환하려면 SDK 에 수십 개의 파라미터를 알맞게 넘겨야 하는데, SDK 를 직접 돌려 볼 수 없으니 무엇을 어떤 값으로 요청할지부터 정확히 정리할 도구가 필요했습니다.

문서를 근거로

SDK 사용법은 웹 문서에 흩어져 있습니다. 이를 모두 모아 에이전트가 참조할 수 있는 데이터로 바꾸고 싶었습니다.

사람은 고르기만

사용자는 선택지를 보고 고르거나, 원하는 값이 없으면 직접 입력합니다. 에이전트가 추천과 이유를 붙여 줍니다.

MCP 로 연결

수업에서 다룬 Tool Calling · MCP 를 활용해, 최종 결과를 SDK MCP 도구 호출(tools/call) 형식으로 내보냅니다.

4실제 동작 화면

예시 모델 mobilenet_v2.onnx 로 앱을 실제 실행해 캡처했습니다. 화면은 ① 모델 업로드 → ② 단계 선택 → ③ 단계별 설정 → ④ SDK MCP 요청 순서로 흘러갑니다.

③ 단계별 설정 — 기본값이 아닌 값으로 바꾸기

단계 탭을 누르면 그 단계의 파라미터 키 · 설명 · 기본값 · 설정 값이 나옵니다. 허용값이 있으면 드롭다운(값 — 설명)으로, 없으면 직접 입력으로 바꿉니다. 설정 값 칸의 색은 회색=기본값, 파랑=선택지에서 변경, 초록=직접 입력, 빨강=문서 밖 값입니다. 이번 예시에서 바꾼 값은 다음과 같습니다.

문서 규칙 점검

서버 app.py 와 모든 모듈은 Python 표준 라이브러리만 사용합니다 (pip 설치 없음, OpenAI API 는 urllib 로 직접 호출).

설계 판단 ① 무엇을 물을지는 코드가, 고르고 설명하는 건 LLM 이

  • 코드(kb.json): 후보 파라미터, 허용값, 기본값, 조건 — 문서에서 온 "정답 범위"
  • LLM: 후보 중 다음 질문 선택, 추천값, 모델 정보에 근거한 추천 이유, "GPU 없어요" 같은 자연어 → 값 해석
  • LLM 이 후보 밖 id · 선택지 밖 값을 내면 버리고 규칙 기반 값으로 대체 (가짜 응답으로 검증)

설계 판단 ② LLM 이 없어도 끝까지 동작

  • 키가 없거나 호출이 실패하면 문서 기본값 · 규칙(모델 shape 로 nchw/nhwc 추정 등)으로 계속 진행
  • 업로드한 모델 파일은 LLM 에 보내지 않고 메타정보만 전달
  • SSH 비밀번호 같은 비밀값은 묻지 않고 ${EAIS_SSH_PASSWD} 자리표시자로만 요청에 넣음

6실제 결과

[SDK MCP 요청 만들기]를 누르면 바꾼 설정 요약과 함께 SDK MCP 로 보낼 tools/call 요청이 만들어집니다.

실제 실행 결과 — 생성된 mobilenet_v2.yaml (발췌)
general:
  device: Gen-8
converter:
  skip_quantization: false
  precision: A16W8
  calibration_mode: default
  calibration_method: percentile
  use_cuda: false
  input_dtype: float32
  graph_opt: common
compiler:
  mode: multicore
실제 실행 결과 — Config/DATA/dbgen_spec.yaml
image_tensor:
  random: False
  path: ./dataset/imagenet_val
  ext: jpg
  shape: (1, 3, 224, 224)
  order: nchw
  dtype: float32
  mean: [0]
  scale: [255]
실제 실행 결과 — 같은 작업의 eais CLI 순서
eais init       --w /home/user/eais-projects/mobilenet_v2
eais generation --w /home/user/eais-projects/mobilenet_v2
eais conversion --w /home/user/eais-projects/mobilenet_v2
eais compile    --w /home/user/eais-projects/mobilenet_v2

개발 중 합성 테스트 모델(동적 batch + Einsum + opset 11)로는 동적 차원 경고, opset 자동 변환 경고, Einsum 미지원 오류, 워크스페이스명 불일치(Error 102) 오류가 잡히는 것을 확인했습니다.

7만들면서 확인한 점

문서를 가져오는 것부터 탐색이었다
SPA 사이트라 일반 fetch 로는 본문이 비어 있었고, JS 번들에서 API 를 찾은 뒤에도 본문 검색 키가 파일명이 아니라 메뉴에 보이는 이름이라는 것을 뷰어 코드에서 확인하고 나서야 10개 문서를 받을 수 있었습니다.
LLM 에게 맡길 범위를 좁히는 것이 핵심
허용값과 조건을 kb.json 에 고정하고 LLM 은 그 안에서만 고르게 하니, LLM 이 없어도 같은 흐름이 동작하고 LLM 이 엉뚱한 값을 내도 걸러낼 수 있었습니다.
화면 흐름은 사용하면서 바뀌었다
처음에는 질문–답변 중심이었지만, 쓰면서 업로드 → 단계 선택 → 단계별 설정 → 요청 순서와 파라미터 표 · 드롭다운 · 색 구분으로 보여 달라는 요청에 맞춰 다시 구성했습니다. 대화형 질문은 탭으로 남겼습니다.
더 발전시킬 부분
  • 실제 SDK MCP 사양을 아직 받지 못해 도구 이름·주소(eais_run_pipeline @ :8790)는 가정값입니다. 사양에 맞춰 arguments 를 조정해야 합니다.
  • 예시 모델 mobilenet_v2 는 가중치를 별도 파일(mobilenet_v2.data, 약 13.9 MB)에 두는데, 현재 요청의 uri 는 .onnx 파일만 가리킵니다. 외부 데이터 파일도 함께 전달하도록 보완이 필요합니다.
  • 이번 캡처는 LLM 키 없이 진행해, LLM 추천 이유가 붙은 화면은 담지 못했습니다.

8결론

SDK 를 직접 쓸 수 없는 상황에서 "무엇을 어떤 값으로 요청할지"를 정리해 주는 에이전트를 만들었습니다. SDK 3.0 문서 10개를 수집해 61개 파라미터의 지식베이스로 바꾸고, 모델 업로드부터 단계별 설정, SDK MCP tools/call 요청 생성까지 실제로 동작하는 것을 mobilenet_v2 로 확인했습니다.

구현하면서 확인한 핵심은, 문서에서 온 정답 범위는 코드가 쥐고 LLM 은 그 안에서 고르고 설명하게 할 때 결과를 믿을 수 있다는 점이었습니다. 다음에는 실제 SDK MCP 사양에 맞춰 요청을 실제로 전송하고 결과를 받아 보는 데까지 이어가 보고 싶습니다.
